Cluster-native reBot cell, overview

The reBot cell tends a printer: it finds the printed part on the bed, picks it, sets it down at A and puts it back. The branch feat/cluster-native-flow moves three steps from manual commands and generated files into skills. Decisions and checks are in cluster_native.html.

What changed

  1. Pose estimator registration. A deploy removes the part's registered pose estimator, which meant running register_using_ioc_train_service by hand. ai.omts.register_pose_estimator now trains and saves it ahead of perception, and returns at once if it is already installed.
  2. Grasp planning. ai.omts.plan_cuboid_grasp turns the estimate into the part's pose and the grasp frames. The rule is a plain function, grasp_math, with unit tests.
  3. Cell layout. ai.omts.configure_cell sets the printer, camera mount, view, A's frames, the part on the bed and the parked parts in one belief-world update. configure_cell --apply runs the host checks first and resets Gazebo after. It replaces the generated files and apply_scene_updates; app_config.yaml is still written.

Status

Blue is in the branch, green was already on main. Full cycles ran in simulation on a local k3s, with the default part and the 3D benchy, in the original layout and a moved one. Nothing has run on the real arm. The skills cannot be previewed, and the pick could not be previewed anyway: a preview of estimate_pose_multi_view returns no estimates. One question is open: whether the tree should read its per-run values from the blackboard, which would remove app_config.yaml.
